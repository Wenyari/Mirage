# 密钥池管理模块更新说明

> 更新日期：2024-12-31
> 基于：`密钥池技术方案.md` 后端架构

---

## 一、核心变更概述

### 架构升级
**原设计**：单层数据库存储
**新设计**：MySQL + Redis 双层架构

- **MySQL**：存储静态配置（model, key_secret, max_concurrency, weight, status）
- **Redis**：维护实时状态（并发计数、熔断标记、统计缓冲）

## 二、API 接口变更

### 2.1 新增字段

| 字段 | 类型 | 说明 | 重要程度 |
|------|------|------|----------|
| `max_concurrency` | number | 最大并发限制（核心配置） | ⭐⭐⭐ |
| `api_base` | string | API 基础地址（支持中转） | ⭐⭐⭐ |
| `current_usage` | number | 当前并发数（从 Redis 实时读取） | ⭐⭐⭐ |
| `is_cooling` | boolean | 是否在冷却期（熔断中） | ⭐⭐⭐ |
| `cooling_until` | string/null | 冷却结束时间 | ⭐⭐ |
| `total_calls` | number | 总调用次数（统计） | ⭐⭐ |
| `total_errors` | number | 总失败次数（统计） | ⭐⭐ |

### 2.2 字段变更

| 字段 | 原类型 | 新类型 | 说明 |
|------|--------|--------|------|
| `status` | string（active/error/rate_limit） | number（0=停用, 1=启用） | 简化为启用/停用两种状态 |
| `key` | string | `key_secret` | 字段名更规范 |

### 2.3 新增接口

1. **`POST /api/admin/keys/batch`** - 批量添加密钥
   - 支持一次导入多个密钥
   - 统一配置并发数和权重

2. **`PATCH /api/admin/keys/{id}`** - 更新密钥配置
   - 修改最大并发数
   - 调整权重
   - 启用/停用密钥

3. **`POST /api/admin/keys/{id}/cooldown`** - 手动熔断控制
   - `action: trigger` - 触发熔断
   - `action: release` - 解除熔断

4. **`GET /api/admin/keys/stats`** - 获取统计信息
   - 按模型分组统计
   - 今日调用/错误数据
   - 错误率计算

5. **`POST /api/admin/keys/health-check`** - 健康检测（路径变更）
   - 原路径：`/api/admin/keys/check`
   - 新路径：`/api/admin/keys/health-check`

## 四、关键技术点

### 4.1 并发控制核心逻辑

**后端（Python）**：
```python
# 原子性占用槽位
current_usage = redis_client.incr(f"pool:usage:{key_id}")
if current_usage <= max_limit:
    # 成功占用
    return selected_key
else:
    # 并发已满，回滚
    redis_client.decr(f"pool:usage:{key_id}")
```

**前端展示**：
- 实时显示 `current_usage` / `max_concurrency`
- Progress Bar 颜色根据使用率变化
- 满载时显示红色警告

### 4.2 熔断机制

**触发条件**（后端自动）：
- API 返回 401（密钥无效）
- API 返回 429（速率限制）

**Redis 存储**：
```
Key: pool:cooldown:{key_id}
Value: "1"
TTL: 300 秒（5分钟）
```

**前端展示**：
- `is_cooling: true` 时显示冷却徽章
- 显示倒计时（cooling_until）
- 支持管理员手动解除

### 4.3 统计数据同步

**Write-Behind 模式**：
1. Redis 缓存增量：`pool:stats:calls:{key_id}`
2. 定时任务（5分钟）同步到 MySQL
3. 前端读取 MySQL 的 `total_calls` 字段

## 五、后端对接注意事项

### 5.1 必须实现的接口

| 接口 | 方法 | 路径 | 优先级 |
|------|------|------|--------|
| 获取密钥列表 | GET | `/api/admin/keys` | P0 |
| 添加密钥 | POST | `/api/admin/keys` | P0 |
| 批量添加 | POST | `/api/admin/keys/batch` | P1 |
| 更新配置 | PATCH | `/api/admin/keys/{id}` | P1 |
| 删除密钥 | DELETE | `/api/admin/keys/{id}` | P0 |
| 熔断控制 | POST | `/api/admin/keys/{id}/cooldown` | P2 |
| 健康检测 | POST | `/api/admin/keys/health-check` | P1 |
| 统计信息 | GET | `/api/admin/keys/stats` | P2 |

### 5.2 实时数据返回

**关键字段必须从 Redis 实时读取**：
- `current_usage`：从 `pool:usage:{key_id}` 读取
- `is_cooling`：检查 `pool:cooldown:{key_id}` 是否存在
- `cooling_until`：计算 TTL 得出结束时间

### 5.3 并发安全

- 使用 Redis INCR/DECR 原子操作
- 避免并发竞态条件
- 释放槽位时防止负数
