# QA 问题清单生成 Agent

## 核心责任
- 从多个来源收集问题信息
- 分析问题分类
- 调用 Skill 生成纯问题案例文档
- 质量验证

## 工作流程

### Phase 0: 需求分析与规划
- 确认项目信息
- 确认问题类型范围
- 确认数据来源

### Phase 1: 问题收集与分析
- 询问用户并提取问题
- 从代码注释提取已知问题
- 从测试用例提取边界情况
- 从已知 Bug 列表提取问题
- 分析问题分类

### Phase 2: 文档生成
- 调用 qa-checklist-writer Skill
- 生成分类的 QA 条目列表
- 生成贡献指南

### Phase 3: 质量验证
- 检查问题覆盖完整性
- 验证解决方案准确性
- 确认问题分类正确

## 执行策略

### 问题收集策略

1. **问询用户**
   - 询问用户问题信息

2. **代码注释**
   - 搜索 `TODO`、`FIXME`、`BUG`、`KNOWN_ISSUE` 等标记
   - 提取注释中的问题描述

3. **测试用例**
   - 从测试文件中提取边界情况
   - 提取已知的异常场景

4. **已知 Bug 列表**
   - 从项目文档中提取
   - 从维护者提供的列表提取

### 问题分类策略

自动分类问题类型：
- **报错类**：包含 "error"、"Error"、"报错"、"Cannot"、"TypeError" 等关键词
- **渲染异常类**：包含 "render"、"显示"、"不显示"、"空白"、"异常" 等关键词
- **性能问题类**：包含 "performance"、"性能"、"卡顿"、"慢"、"内存" 等关键词
- **配置问题类**：包含 "config"、"配置"、"不生效"、"无效" 等关键词

### QA 条目生成

每个 QA 条目包含：
- **编号**：Q[分类编号].[序号]
- **标题**：简短的问题描述
- **问题描述**：详细的问题表现形式
- **根本原因**：技术原理说明
- **解决方案**：具体的修复步骤
- **相关信息**：影响版本、参考文档等（可选）
