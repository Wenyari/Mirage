# decision-tree-writer Agent 改进说明

## 改进日期
2025-12-01

## 改进背景

### 问题描述
在使用 `decision-tree-writer` agent 生成**配置项文档**时，由于需要处理大量配置项，导致上下文（context）过大，最终生成的文档内容不完整，很多部分因为 token 限制而无法写出。

### 根本原因
原有工作流程试图在一次会话中处理所有配置项的详细信息，导致：
1. 一次性加载所有配置项的类型定义
2. 所有配置项的上下文同时存在于会话中
3. Token 使用量超限，导致内容生成不完整

---

## 改进方案

### 核心思路：分而治之

采用 **配置项收集 → 目录规划 → 分块编写** 的三阶段策略：

```
Phase 0: 配置项收集与目录规划
  ↓
  ├─ 收集所有配置项（只收集名称和路径，不加载详细定义）
  ├─ 生成配置项目录树
  ├─ 将配置项划分成多个子文档
  └─ 制定编写计划（使用 TodoWrite）
  ↓
Phase 1-2: 逐个编写子文档
  ↓
  对每个子文档：
    ├─ 只读取当前子文档相关的配置项定义
    ├─ 生成该子文档
    ├─ 标记为完成
    └─ 移到下一个子文档
  ↓
Phase 3: 生成主目录和索引
```

---

## 具体改进内容

### 1. 新增 Phase 0：配置项收集与目录规划

**位置**：`.claude/agents/decision-tree-writer.md` 第 78-173 行

**功能**：
- **0.1 收集所有配置项**：使用 Glob/Grep 搜索配置定义，只收集名称、路径、所属模块
- **0.2 生成配置项目录树**：整理成树形结构，保存到 `docs/configuration/config-index.md`
- **0.3 规划子文档划分**：按模块/组件划分（每个子文档 20-50 个配置项）
- **0.4 制定编写计划**：使用 TodoWrite 创建详细计划，向用户展示并获得确认

**关键原则**：
> ⚠️ 重要：当创建**配置手册**类型的文档时，必须先执行此阶段，避免因上下文过大导致内容不完整。

---

### 2. 更新 Phase 2：文档生成（分块处理策略）

**位置**：`.claude/agents/decision-tree-writer.md` 第 222-278 行

**核心原则**：
- ✅ **每次只处理一个子文档**
- ✅ **避免加载其他子文档的配置项信息**
- ✅ **使用 config-index.md 作为导航中枢**
- ❌ **不要一次性读取所有配置项的类型定义**

**分块编写流程**：
```markdown
步骤1: 生成配置项目录树（config-index.md）
步骤2: 逐个编写子文档（使用 TodoWrite 跟踪进度）
  对每个子文档：
    1. 标记为 in_progress
    2. 只读取当前子文档相关的配置项定义
    3. 使用 decision-tree-writer Skill 生成
    4. 标记为 completed
    5. 移到下一个子文档
步骤3: 生成主目录（README.md）
```

## 改进效果

### 解决的问题
1. ✅ **避免上下文溢出**：每次只处理一个子文档，不会同时加载所有配置项
2. ✅ **内容完整性保证**：分块编写确保每个子文档都有足够的 token 预算
3. ✅ **可维护性提升**：配置项按模块划分，便于后续更新和维护
4. ✅ **进度可追踪**：使用 TodoWrite 让用户清楚了解编写进度

### 适用场景
- **配置手册**：必须使用新的分块策略
- **QA清单/故障排查指南**：
  - 内容较少：使用原有流程
  - 内容过多：也可采用分块策略

## 使用指导

### 对于用户
当你需要生成配置手册时，agent 会自动：
1. 先收集所有配置项并生成目录树
2. 向你展示子文档划分方案
3. 等待你的确认后再开始编写
4. 逐个编写子文档，每次只关注一个模块

### 对于 Agent
执行配置手册任务时，务必：
1. **先执行 Phase 0**，不要跳过
2. **使用 TodoWrite** 创建并跟踪编写计划
3. **严格分块处理**，每次只读取当前子文档的配置项
4. **向用户展示计划**，获得确认后再执行

## 总结

这次改进通过引入 **分而治之** 的策略，彻底解决了配置手册生成时的上下文溢出问题。核心思想是：

> **不要试图在一次会话中处理所有内容，而是先规划，再分块，逐个击破。**

这个思路不仅适用于配置文档，也可以应用到其他需要处理大量信息的文档生成任务中。
