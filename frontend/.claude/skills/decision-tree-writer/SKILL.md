## 核心功能

本 Skill 用于生成结构化的决策树形式文档，适用于：
- **配置手册**：指导用户进行配置决策
- **QA清单**：帮助可视化库使用者自助排查问题、快速定位 bug 根源
- **故障排查指南**：按症状进行诊断

## 工作流程

### 1. 输入分析
- 理解文档的目标对象（用户/QA/运维）
- 识别关键决策点
- 列举所有可能的分支

### 2. 决策树设计
遵循以下结构：

```
决策树
├── 根节点（初始状态）
├── 决策节点
│   ├── 条件A
│   │   ├── 子决策
│   │   └── 终止节点（建议/结果）
│   └── 条件B
│       └── 终止节点（建议/结果）
└── 所有分支都应导向明确的结果
```

### 3. 文档生成

#### 格式：Markdown + Mermaid 图示

```markdown
## 决策树

### 文本形式
如果 [条件A]？
  - 是 → [建议A]
  - 否 → 继续

继续：如果 [条件B]？
  - 是 → [建议B]
  - 否 → [建议C]

### 图示形式
\`\`\`mermaid
graph TD
    A[开始] --> B{条件A?}
    B -->|是| C[建议A]
    B -->|否| D{条件B?}
    D -->|是| E[建议B]
    D -->|否| F[建议C]
\`\`\`
```

### 4. 检查清单

每个决策树应包含：

- [ ] 所有分支都有明确的终止状态
- [ ] 每个决策点都有2-3个清晰选项
- [ ] 没有死循环
- [ ] 已包含所有常见场景
- [ ] 用户易于理解和实施

## 规范要求

### 1. 清晰性
- 决策点必须是是/否问题或单选
- 避免模糊的表述
- 每个分支都有明确的结果

### 2. 完整性
- 覆盖所有常见场景
- 提供异常情况处理
- 包含回滚或重试路径

### 3. 可维护性
- 使用 Mermaid 图示便于更新
- 提供文本版本作为备份
- 记录最后更新时间和版本号

### 4. 深度控制
- 决策树深度不超过 4 层
- 在适当位置合并相似分支
- 考虑提供"快速路径"和"详细路径"

## 使用指导

### 设计决策点时
- 使用 是/否 问题或清晰的单选选项
- 避免多选或模糊的决策
- 每个决策点最多 3-4 个分支

### 设计终止状态时
- 提供明确的建议或行动
- 包含具体的参数/配置值
- 指向相关文档或代码的链接
- 说明如何验证配置正确

### Mermaid 图表规范
- 使用 `graph TD` (自上而下) 或 `graph LR` (从左到右)
- 决策节点使用菱形 `{}`
- 终止节点使用矩形 `[]` 或圆角矩形 `()`
- 重要节点可用双边框 `[[ ]]`
- 添加清晰的连接标签

## 权限

本 Skill 需要以下工具权限：
- `Read` - 读取项目文件和现有文档
- `Write` - 生成决策树文档
- `Glob` / `Grep` - 搜索相关配置和代码
- `AskUserQuestion` - 与用户交互澄清需求
