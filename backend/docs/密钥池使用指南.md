# 密钥池系统使用指南

## 概述

密钥池系统是一个基于 Redis 的高性能 API 密钥调度和任务执行系统，支持：

- 🔑 **多密钥负载均衡** - 权重随机分配
- 🚀 **并发控制** - 每个密钥独立的并发限制
- ⚡ **VIP 插队** - T4/T5 用户优先处理
- 🔄 **自动熔断** - 异常密钥自动隔离
- 📊 **实时进度** - Redis 高频读写，数据库持久化
- 🎯 **惰性取消** - 用户取消任务自动跳过
- 🔧 **多渠道支持** - 支持不同 API 提供商的路径配置

## 系统架构

```
用户请求 → API Layer → TaskService → KeyManager
                                         ↓
                           [密钥分配] → 执行队列 (queue:runnable)
                                         ↓
                                       Worker
                                         ↓
                           上游 API ← [轮询进度]
                                         ↓
                           任务完成 → 释放密钥 → 触发下一个任务
```

## 快速开始

### 1. 数据库初始化

```bash
python init_db.py
```

这将创建所有必需的表，包括：
- `api_keys` - 密钥池配置表
- `tasks` - 任务记录表
- `models` - 模型基本信息表
- `model_configs` - 模型配置表
- `membership_configs` - 会员等级配置表

### 2. 配置 API 密钥

在管理后台或直接通过数据库添加 API 密钥：

```sql
INSERT INTO api_keys (model, api_base, key_secret, max_concurrency, weight, status) VALUES
('sora', 'https://api.openai.com/v1/videos/generations', 'sk-xxxxx', 3, 10, 1),
('sora', 'https://relay-a.com/v2/gen', 'sk-yyyyy', 5, 20, 1);
```

**重要配置说明**：

- `api_base`: 完整的任务提交端点地址（含协议、域名和路径）
  - 示例：`https://api.openai.com/v1/videos/generations`
  - 查询路径自动拼接：`{api_base}/{task_id}`
  - 特殊情况（查询路径不同）：使用 `|` 分隔，如 `提交地址|查询地址`
- `key_secret`: API 密钥
- `max_concurrency`: 该密钥的最大并发数
- `weight`: 权重（1-100），越高越容易被选中
- `status`: 1=启用, 0=停用

### 3. 启动服务

需要启动 3 个进程：

#### 3.1 启动 API 服务

```bash
python run.py
```

#### 3.2 启动 Worker（任务执行器）

```bash
python worker.py
```

Worker 负责：
- 监听 `queue:runnable` 队列
- 调用上游 API 执行任务
- 轮询任务进度并更新到 Redis
- 完成后释放密钥并触发下一个任务调度

#### 3.3 启动 Scheduler（定时维护）

```bash
python scheduler.py
```

Scheduler 负责：
- **统计同步**（每 5 分钟）: 将 Redis 中的统计数据同步到 MySQL
- **看门狗**（每 1 分钟）: 检测并修复队列死锁

## 核心功能说明

### 密钥分配策略

1. **快车道**: 任务提交时尝试立即获取密钥
   - 如果有空闲密钥 → 直接进入执行队列
   - 如果无空闲密钥 → 进入等待队列

2. **等待队列分流**:
   - VIP 队列 (`queue:waiting:vip`) - T4/T5 用户
   - 普通队列 (`queue:waiting:normal`) - T1-T3 用户

3. **权重随机选择**:
   - 根据密钥的 `weight` 字段进行加权随机
   - 权重越高，被选中的概率越大

### 并发控制

每个密钥有独立的并发限制 (`max_concurrency`)：

```
密钥 A: max_concurrency = 3
密钥 B: max_concurrency = 5

总并发能力 = 8
```

Redis 键：`pool:usage:{key_id}` 记录当前并发数

### 自动熔断

当密钥出现以下情况时自动熔断（默认 5 分钟）：

- HTTP 401/403 - 认证失败
- HTTP 429 - 速率限制
- 其他 API 错误

Redis 键：`pool:cooldown:{key_id}` 标记熔断状态

### VIP 插队

密钥释放时的调度优先级：

```python
1. 先检查 VIP 队列 (queue:waiting:vip)
2. 如果 VIP 队列为空，再检查普通队列 (queue:waiting:normal)
```

### 惰性取消

用户取消任务时：
1. 只修改数据库状态为 `cancelled`
2. 不从 Redis 队列中删除
3. Worker 取出时检查状态，如果已取消则跳过并继续处理下一个

### 实时进度

- **Worker 写入**: `task:progress:{task_id}` (Redis)
- **API 读取**: 从 Redis 读取实时进度
- **数据库持久化**: 任务完成后写入 `tasks.progress` 字段

## API 使用示例

### 提交任务

```bash
POST /api/tasks
Authorization: Bearer <jwt_token>

{
  "model": "sora",
  "prompt": "A beautiful sunset over the ocean",
  "params": {
    "duration": 5,
    "quality": "hd"
  }
}
```

响应：

```json
{
  "code": 200,
  "msg": "Task is being processed",
  "data": {
    "task_id": "uuid-xxx",
    "status": "pending"
  }
}
```

### 查询任务状态

```bash
GET /api/tasks/{task_id}
Authorization: Bearer <jwt_token>
```

响应：

```json
{
  "code": 200,
  "msg": "Success",
  "data": {
    "id": "uuid-xxx",
    "status": "processing",
    "progress": 45,
    "result_url": null,
    "fail_reason": null,
    "created_at": "2025-01-04T12:00:00"
  }
}
```

### 取消任务

```bash
POST /api/tasks/{task_id}/cancel
Authorization: Bearer <jwt_token>
```

响应：

```json
{
  "code": 200,
  "msg": "Task cancelled successfully",
  "data": null
}
```

## Redis 键说明

| 键格式 | 类型 | TTL | 说明 |
|--------|------|-----|------|
| `pool:usage:{key_id}` | String (Int) | 24h | 密钥当前并发计数 |
| `pool:cooldown:{key_id}` | String | 300s | 密钥熔断标记 |
| `pool:stats:calls:{key_id}` | String (Int) | - | 密钥调用次数缓冲 |
| `task:progress:{task_id}` | String (Int) | 24h | 任务实时进度 |
| `queue:waiting:vip` | List | - | VIP 等待队列 |
| `queue:waiting:normal` | List | - | 普通等待队列 |
| `queue:runnable` | List | - | 执行队列 |

## 故障排查

### 任务一直处于 pending 状态

可能原因：
1. Worker 没有启动
2. 所有密钥都在熔断中
3. 所有密钥的并发已满

解决方法：
```bash
# 检查 Worker 是否运行
ps aux | grep worker.py

# 检查密钥状态
redis-cli
> KEYS pool:cooldown:*

# 检查队列积压
redis-cli
> LLEN queue:waiting:vip
> LLEN queue:waiting:normal
```

### 密钥频繁熔断

可能原因：
1. API 密钥无效或过期
2. 速率限制过低
3. `api_base` 配置错误

解决方法：
- 检查密钥是否有效
- 调整 `max_concurrency` 设置
- 验证 `api_base` 地址是否正确

### 统计数据不同步

可能原因：
- Scheduler 没有启动

解决方法：
```bash
python scheduler.py
```

## 性能优化建议

1. **调整并发限制**: 根据上游 API 的速率限制调整 `max_concurrency`
2. **权重配置**: 给高性能密钥设置更高的 `weight`
3. **多密钥配置**: 同一模型配置多个密钥以提升并发能力
4. **Redis 优化**: 使用 Redis 持久化（AOF）防止数据丢失

## 扩展性

### 支持新的 API 提供商

只需在 `api_keys` 表中添加新的记录：

```sql
INSERT INTO api_keys (model, api_base, key_secret, max_concurrency, weight, status) VALUES
('sora', 'https://new-provider.com/api/v1/tasks', 'sk-zzzzz', 10, 15, 1);
```

### 水平扩展

可以启动多个 Worker 进程以提升处理能力：

```bash
# 终端 1
python worker.py

# 终端 2
python worker.py

# 终端 3
python worker.py
```

所有 Worker 共享同一个 Redis 队列，自动负载均衡。

## 技术架构亮点

1. ✅ **事件驱动调度** - 密钥释放时主动触发下一个任务
2. ✅ **原子性操作** - 使用 Redis INCR 保证并发安全
3. ✅ **读写分离** - Redis 承载高频读写，MySQL 持久化
4. ✅ **零配置扩展** - 支持任意 API 路径格式
5. ✅ **故障自愈** - 看门狗自动修复队列死锁
