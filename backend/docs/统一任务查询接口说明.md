# 统一任务查询接口说明

## 接口概述

**接口地址：** `GET /api/tasks/{task_id}`

**核心特性：** 通过本地任务ID，智能返回不同阶段的信息
- ✅ **排队中**：返回队列位置信息
- ✅ **执行中**：返回实时进度（0-100）
- ✅ **已完成**：返回最终结果或失败原因

## 工作原理

### 数据流程

```
用户提交任务
    ↓
系统生成本地ID (uuid)
    ↓
任务状态 = pending
    ↓
┌─────────────────────────┬──────────────────────────┐
│  有可用密钥              │  无可用密钥               │
│  → queue:runnable       │  → queue:waiting:*       │
└─────────────────────────┴──────────────────────────┘
              ↓
    Worker 取出任务处理
              ↓
    提交到上游API (获得 upstream_task_id)
              ↓
    保存到数据库: task.upstream_task_id
              ↓
    轮询上游进度，写入 Redis: task:progress:{本地task_id}
              ↓
    任务完成，更新数据库状态
```

### 智能查询逻辑

```python
def get_task_status(task_id):
    """通过本地任务ID统一查询"""

    task = Task.query.get(task_id)  # 使用本地ID查询

    if task.status == 'pending':
        # 任务在队列中，返回排队信息
        return {
            "status": "pending",
            "queue_info": {
                "user_queue": "vip" | "normal",
                "position": 10,  # 队列位置
                "vip_queue": 5,
                "normal_queue": 20
            }
        }

    elif task.status == 'processing':
        # 任务执行中，从 Redis 读取实时进度
        progress = redis.get(f"task:progress:{task_id}")
        return {
            "status": "processing",
            "progress": 45,  # 0-100
            "upstream_task_id": "upstream-xxx"  # 上游任务ID
        }

    else:  # success, failed, cancelled
        # 任务已完成，返回数据库中的最终结果
        return {
            "status": "success",
            "progress": 100,
            "result_url": "https://...",
            "upstream_task_id": "upstream-xxx"
        }
```

## 前端轮询策略

### 推荐轮询间隔

```javascript
function getPollingInterval(status) {
    switch(status) {
        case 'pending':
            return 2000;  // 2秒（排队变化较快）
        case 'processing':
            return 3000;  // 3秒（进度更新较慢）
        default:  // success, failed, cancelled
            return null;  // 停止轮询
    }
}
```

### 完整示例

```javascript
class TaskMonitor {
    constructor(taskId, token) {
        this.taskId = taskId;
        this.token = token;
        this.pollTimer = null;
    }

    async start() {
        await this.poll();
    }

    async poll() {
        try {
            const response = await fetch(`/api/tasks/${this.taskId}`, {
                headers: { 'Authorization': `Bearer ${this.token}` }
            });

            const result = await response.json();

            if (result.code !== 200) {
                console.error('Failed to get task status');
                return;
            }

            const task = result.data;
            this.updateUI(task);

            // 根据状态决定是否继续轮询
            const interval = this.getPollingInterval(task.status);
            if (interval) {
                this.pollTimer = setTimeout(() => this.poll(), interval);
            }

        } catch (error) {
            console.error('Poll error:', error);
            // 发生错误也继续轮询
            this.pollTimer = setTimeout(() => this.poll(), 3000);
        }
    }

    updateUI(task) {
        switch(task.status) {
            case 'pending':
                this.showQueueStatus(task.queue_info);
                break;
            case 'processing':
                this.showProgress(task.progress);
                break;
            case 'success':
                this.showResult(task.result_url);
                this.stop();
                break;
            case 'failed':
                this.showError(task.fail_reason);
                this.stop();
                break;
            case 'cancelled':
                this.showCancelled();
                this.stop();
                break;
        }
    }

    showQueueStatus(queueInfo) {
        const queueType = queueInfo.user_queue === 'vip' ? 'VIP' : '普通';
        document.getElementById('status').textContent = '排队中';
        document.getElementById('queue-info').textContent =
            `${queueType}通道 - 前面还有 ${queueInfo.position} 个任务`;
    }

    showProgress(progress) {
        document.getElementById('status').textContent = '生成中';
        document.getElementById('progress-bar').style.width = `${progress}%`;
        document.getElementById('progress-text').textContent = `${progress}%`;
    }

    showResult(resultUrl) {
        document.getElementById('status').textContent = '完成';
        document.getElementById('result').innerHTML =
            `<video src="${resultUrl}" controls></video>`;
    }

    showError(reason) {
        document.getElementById('status').textContent = '失败';
        document.getElementById('error').textContent = reason;
    }

    showCancelled() {
        document.getElementById('status').textContent = '已取消';
    }

    getPollingInterval(status) {
        switch(status) {
            case 'pending': return 2000;
            case 'processing': return 3000;
            default: return null;
        }
    }

    stop() {
        if (this.pollTimer) {
            clearTimeout(this.pollTimer);
            this.pollTimer = null;
        }
    }
}

// 使用示例
const monitor = new TaskMonitor('abc-123-def-456', 'user-token');
monitor.start();
```

## 关键字段说明

| 字段 | 类型 | 说明 | 何时有值 |
|------|------|------|----------|
| `id` | string | 本地任务ID（前端使用） | 创建时 |
| `upstream_task_id` | string | 上游API任务ID（内部使用） | Worker提交后 |
| `status` | string | 任务状态（pending/processing/success/failed/cancelled） | 创建时 |
| `progress` | int | 任务进度 0-100 | processing时 |
| `queue_info` | object | 排队信息 | pending时 |
| `result_url` | string | 结果链接 | success时 |
| `fail_reason` | string | 失败原因 | failed时 |

## 核心优势

### ✅ 前端简单
- 只需要知道本地任务ID
- 无需关心上游任务ID
- 一个接口获取所有信息

### ✅ 智能返回
- pending → 队列信息
- processing → 实时进度
- 完成 → 最终结果

### ✅ 无缝切换
- 状态变化时数据结构自动适配
- 前端根据 status 字段判断展示逻辑

### ✅ 性能优化
- pending：查询 Redis 队列长度
- processing：查询 Redis 进度缓存
- 完成：查询数据库（不轮询）

## 常见问题

### Q: 为什么需要 upstream_task_id？
A: 用于 Worker 轮询上游API进度，前端不需要关心。

### Q: progress 什么时候更新？
A:
- pending：始终为 0
- processing：每3秒从上游API获取并更新到Redis
- 完成：固定为 100 或 0（失败）

### Q: queue_info 什么时候返回？
A: 只有 status='pending' 时返回，其他状态不返回此字段。

### Q: 轮询多久停止？
A: status 变为 success/failed/cancelled 时停止轮询。

### Q: 如果上游API很慢怎么办？
A: Worker 最多轮询10分钟（600秒），超时后标记为 failed 并退款。

## 总结

通过本地任务ID，一个接口就能获取任务的所有信息：
- ✅ 排队信息（pending）
- ✅ 实时进度（processing）
- ✅ 最终结果（success/failed）

前端只需要根据 `status` 字段判断展示逻辑，无需关心底层的 upstream_task_id 和 Redis 存储细节。
