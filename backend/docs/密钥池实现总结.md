### 2. 技术问题修复

#### 2.1 Redis 客户端导入问题
**问题**：Python 导入机制导致 `redis_client` 在导入时为 `None`

**解决方案**：
```python
# 错误方式
from app.extensions import redis_client
redis_client.get(...)  # redis_client 是 None

# 正确方式
class KeyManager:
    @classmethod
    def _get_redis(cls):
        from app.extensions import redis_client
        return redis_client

    @classmethod
    def some_method(cls):
        cls._get_redis().get(...)  # 动态获取
```

#### 2.2 看门狗返回值问题
**问题**：`watchdog()` 在无任务时返回 `None`，导致比较错误

**解决方案**：
```python
# 修改前
if vip_waiting == 0 and normal_waiting == 0:
    return  # 返回 None

# 修改后
if vip_waiting == 0 and normal_waiting == 0:
    return 0  # 返回 0
```

#### 2.3 测试用例 SQLAlchemy 会话问题
**问题**：尝试刷新已从会话分离的对象

**解决方案**：
```python
# 错误方式
result = TaskService.submit_task(test_user.id, task_data)
db_session.session.refresh(test_user)  # test_user 已分离

# 正确方式
user_id = test_user.id
result = TaskService.submit_task(user_id, task_data)
user = User.query.get(user_id)  # 重新查询
assert user.balance < initial_balance
```

```

│                      用户请求                            │
└─────────────────────────────────────────────────────────┘
                         ↓
┌─────────────────────────────────────────────────────────┐

│  - POST /api/tasks                                       │
│  - GET  /api/tasks/{id}                                  │
│  - POST /api/tasks/{id}/cancel                           │
└─────────────────────────────────────────────────────────┘
                         ↓
┌─────────────────────────────────────────────────────────┐
│  TaskService                                             │
│  - 验证权限和余额                                         │
│  - 检查并发限制                                           │
│  - 扣除积分                                               │
│  - 创建任务记录                                           │
└─────────────────────────────────────────────────────────┘
                         ↓
┌─────────────────────────────────────────────────────────┐
│  KeyManager.allocate_key()                               │
│  - 查询可用密钥                                           │
│  - 权重随机选择                                           │
│  - 原子性占用                                             │
└─────────────────────────────────────────────────────────┘
         ↓ 有密钥                    ↓ 无密钥
┌──────────────────┐        ┌──────────────────┐
│ queue:runnable   │        │ queue:waiting:*  │
│ (执行队列)        │        │ (等待队列)        │
└──────────────────┘        └──────────────────┘
         ↓                           ↓
┌─────────────────────────────────────────────────────────┐
│  Worker (worker.py)                                      │
│  - 监听执行队列                                           │
│  - 调用上游 API                                          │
│  - 轮询进度                                               │
│  - 更新 Redis 实时进度                                   │
│  - 完成后释放密钥                                         │
└─────────────────────────────────────────────────────────┘
                         ↓
┌─────────────────────────────────────────────────────────┐
│  KeyManager.release_key_and_dispatch()                   │
│  - 释放密钥占用                                           │
│  - 从等待队列取任务（VIP 优先）                           │
│  - 惰性取消检查                                           │
│  - 注入密钥信息                                           │
│  - 推送到执行队列                                         │
└─────────────────────────────────────────────────────────┘
                         ↓ (循环)
                    Worker 继续处理

         定时任务 (scheduler.py)
┌─────────────────────────────────────────────────────────┐
│  统计同步 (每 5 分钟)                                     │
│  - Redis stats → MySQL                                   │
│                                                          │
│  看门狗 (每 1 分钟)                                       │
│  - 检测队列积压                                           │
│  - 触发空闲密钥调度                                       │
└─────────────────────────────────────────────────────────┘
```

## 核心特性

### 1. api_base 灵活配置
- 存储完整端点地址（如 `https://api.openai.com/v1/videos/generations`）
- 默认查询路径：`{api_base}/{task_id}`
- 特殊情况支持：`提交地址|查询地址`

### 2. VIP 插队机制
- T4/T5 用户 → `queue:waiting:vip`
- T1-T3 用户 → `queue:waiting:normal`
- 密钥释放时优先处理 VIP 队列

### 3. 自动熔断与恢复
- HTTP 401/403/429 → 自动熔断 5 分钟
- Redis 标记：`pool:cooldown:{key_id}`

### 4. 实时进度追踪
- Worker 写入：`task:progress:{task_id}` (Redis)
- API 读取实时进度
- 完成后持久化到数据库

### 5. 惰性取消
- 用户取消 → 只修改 DB 状态
- Worker 取出时检查 → 自动跳过并继续

### 6. 事件驱动调度
- 密钥释放时主动触发下一个任务
- 看门狗定期检测并修复死锁

## 启动指南

### 1. 初始化数据库
```bash
python init_db.py
```

### 2. 配置 API 密钥
在数据库中配置密钥：
```sql
INSERT INTO api_keys (model, api_base, key_secret, max_concurrency, weight, status) VALUES
('sora-2', 'https://ai.t8star.cn/v2/videos/generations', 'sk-xxxxx', 3, 10, 1);
```

### 3. 启动服务（3 个进程）
```bash
# 终端 1: API 服务
python run.py

# 终端 2: Worker
python worker.py

# 终端 3: Scheduler
python scheduler.py
```

## 故障排查

### Worker 无法启动
- 检查 Redis 连接
- 检查数据库连接

### 任务一直 pending
- 检查 Worker 是否运行
- 检查是否有可用密钥：`SELECT * FROM api_keys WHERE status=1`
- 检查密钥是否在熔断：`redis-cli KEYS pool:cooldown:*`

### 队列积压
- 增加 Worker 进程数
- 增加密钥并发限制
- 添加更多密钥

## 性能优化
