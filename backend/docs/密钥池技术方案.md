# 密钥池管理模块 (Key Pool Manager) 技术方案

## 1. 模块概述 (Module Overview)

**密钥池管理模块**是系统的“弹药库”，负责统一管理上游 API Key（如 OpenAI, Sora, Midjourney）。该模块完全独立于用户（User）和任务（Task）逻辑，通过 **MySQL 存储配置** + **Redis 维护实时状态** 的架构，实现以下核心目标：

1. **高并发控制**：精确限制每个 Key 的并发数，防止触发上游封号。
2. **负载均衡**：基于**权重 (Weight)** 的随机轮询，支持“大号”和“小号”混合使用。
3. **自动熔断**：自动检测失效或限流的 Key，触发冷却（Cooldown），并在冷却结束后自动恢复。
4. **高性能统计**：利用 Redis 缓冲调用计数，定时同步回 MySQL，避免高频写库。

---

## 2. 架构设计 (Architecture)

* **配置层 (MySQL)**: 存储 Key 的静态属性（密钥串、最大并发、权重）。
* **状态层 (Redis)**:
* **并发计数器**: 记录 Key 当前占用的槽位。
* **熔断标记**: 标记不健康的 Key。
* **统计缓冲区**: 暂存 `total_calls` 增量。


* **逻辑层 (Service)**: 提供 `allocate` (申请), `release` (释放), `mark_unhealthy` (报错) 接口。

## 3. 数据库设计 (MySQL Schema)

在 `app/models/key.py` 中定义。

```sql
CREATE TABLE `api_keys` (
  `id` INT AUTO_INCREMENT PRIMARY KEY,
  `platform` VARCHAR(50) NOT NULL COMMENT '平台标识: openai, sora, midjourney',
  `key_secret` VARCHAR(512) NOT NULL COMMENT '密钥本体 (建议加密存储)',
  `max_concurrency` INT DEFAULT 3 COMMENT '最大并发限制 (核心配置)',
  `weight` TINYINT DEFAULT 10 COMMENT '权重, 用于轮询概率控制',
  `status` TINYINT DEFAULT 1 COMMENT '1=启用, 0=手动停用',
  
  -- 统计字段 (由定时任务异步更新)
  `total_calls` INT DEFAULT 0 COMMENT '总调用次数',
  `total_errors` INT DEFAULT 0 COMMENT '总失败次数',
  
  `last_used_at` DATETIME NULL COMMENT '最后活跃时间',
  `created_at` DATETIME DEFAULT CURRENT_TIMESTAMP,
  
  INDEX `idx_platform_status` (`platform`, `status`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='密钥池配置表';

```

## 4. Redis 数据结构设计

为避免 Key 冲突，使用统一前缀：

| Redis Key 格式 | 数据类型 | TTL | 作用 |
| --- | --- | --- | --- |
| `pool:usage:{key_id}` | String (Int) | 24h | **并发计数器**：当前正在运行的任务数。 |
| `pool:cooldown:{key_id}` | String | 300s | **熔断标记**：存在则跳过该 Key (冷却中)。 |
| `pool:stats:calls:{key_id}` | String (Int) | 无 | **调用计数缓冲**：记录新增的调用次数，定时刷入 DB。 |

## 5. 核心逻辑实现 (`app/services/key_manager.py`)

```python
import random
import logging
from app.extensions import db, redis_client
from app.models.key import ApiKey
from sqlalchemy import text

logger = logging.getLogger(__name__)

class KeyManager:
    # Redis 前缀
    PREFIX_USAGE = "pool:usage"
    PREFIX_COOLDOWN = "pool:cooldown"
    PREFIX_STATS_CALLS = "pool:stats:calls"
    
    # 配置常量
    COOLDOWN_SECONDS = 300  # 熔断冷却 5 分钟

    @classmethod
    def allocate_key(cls, platform: str):
        """
        [核心] 申请一个可用 Key
        逻辑：获取候选 -> 过滤冷却 -> 权重随机 -> 原子占用 -> 记录统计
        """
        # 1. 获取所有候选 Key (生产环境建议加内存缓存 60s)
        all_candidates = ApiKey.query.filter_by(platform=platform, status=1).all()
        
        # 2. 预先过滤掉 "冷却中" 的 Key
        valid_candidates = []
        for key_obj in all_candidates:
            if not redis_client.get(f"{cls.PREFIX_COOLDOWN}:{key_obj.id}"):
                valid_candidates.append(key_obj)
        
        if not valid_candidates:
            logger.warning(f"No active keys available for platform: {platform}")
            return None

        # 3. 准备权重数据
        weights = [key.weight for key in valid_candidates]

        # 4. 尝试获取 (最多尝试 N 次，防止随机一直选中满载的 Key)
        max_attempts = len(valid_candidates) * 2
        for _ in range(max_attempts):
            
            # 【权重算法】基于权重的随机选择
            # random.choices 返回列表，取 [0]
            selected_key = random.choices(valid_candidates, weights=weights, k=1)[0]
            
            key_id = selected_key.id
            max_limit = selected_key.max_concurrency

            # 5. 【并发控制】原子性占用
            # INCR 操作：先加1，如果发现超标了再减回去
            current_usage = redis_client.incr(f"{cls.PREFIX_USAGE}:{key_id}")
            
            if current_usage <= max_limit:
                # === 成功获取 ===
                
                # 【统计缓冲】在 Redis 中记录一次调用（Write-Behind）
                redis_client.incr(f"{cls.PREFIX_STATS_CALLS}:{key_id}")
                
                logger.info(f"Key {key_id} allocated. Usage: {current_usage}/{max_limit}")
                return selected_key
            else:
                # === 并发已满 ===
                # 回滚计数
                redis_client.decr(f"{cls.PREFIX_USAGE}:{key_id}")
                # 继续下一次循环尝试
                continue
        
        logger.warning(f"All keys for {platform} are busy.")
        return None

    @classmethod
    def release_key(cls, key_id: int):
        """
        [核心] 释放 Key 的并发占用
        必须在任务结束(无论成功失败)的 finally 块中调用
        """
        redis_key = f"{cls.PREFIX_USAGE}:{key_id}"
        
        # 保证不减成负数
        current = redis_client.get(redis_key)
        if current and int(current) > 0:
            redis_client.decr(redis_key)
        else:
            # 异常修正
            redis_client.set(redis_key, 0)

    @classmethod
    def mark_as_unhealthy(cls, key_id: int, error_msg: str = ""):
        """
        [核心] 触发熔断
        当 API 返回 401(无效) 或 429(限流) 时调用
        """
        # 设置冷却 TTL，期间 allocate_key 不会再选中它
        redis_client.setex(
            f"{cls.PREFIX_COOLDOWN}:{key_id}", 
            cls.COOLDOWN_SECONDS, 
            "1"
        )
        logger.warning(f"Key {key_id} marked unhealthy. Reason: {error_msg}")

    @classmethod
    def sync_stats_to_db(cls):
        """
        [定时任务] 数据持久化
        将 Redis 中的增量调用次数同步回 MySQL。建议每 5 分钟运行一次。
        """
        pattern = f"{cls.PREFIX_STATS_CALLS}:*"
        keys = redis_client.keys(pattern)
        
        if not keys: return

        for r_key in keys:
            try:
                # 解析 ID
                key_str = r_key.decode('utf-8')
                key_id = int(key_str.split(':')[-1])
                
                # 【核心】原子性获取并清零 (GetSet)
                delta_calls = redis_client.getset(r_key, 0)
                
                if delta_calls and int(delta_calls) > 0:
                    delta = int(delta_calls)
                    # 执行原生 SQL 更新
                    sql = text("UPDATE api_keys SET total_calls = total_calls + :delta WHERE id = :id")
                    db.session.execute(sql, {"delta": delta, "id": key_id})
            except Exception as e:
                logger.error(f"Sync failed for {r_key}: {e}")
        
        db.session.commit()

```

## 6. 定时任务配置 (Scheduled Tasks)

为了持久化 `total_calls`，需要在系统启动时挂载 APScheduler。

**文件**: `app/__init__.py` 或 `run.py`

```python
from apscheduler.schedulers.background import BackgroundScheduler
from app.services.key_manager import KeyManager

def init_key_sync_scheduler(app):
    scheduler = BackgroundScheduler()
    # 每 5 分钟同步一次 MySQL
    scheduler.add_job(
        func=KeyManager.sync_stats_to_db, 
        trigger="interval", 
        minutes=5, 
        id='sync_key_stats',
        replace_existing=True
    )
    scheduler.start()

```

## 7. 外部模块接入指南 (Integration)

### 步骤 A: 任务提交阶段 (Task Service)

在任务入队前，**先锁定一个 Key**。如果拿不到 Key，说明资源耗尽，直接报错，不入队。

```python
# app/services/task_service.py
from app.services.key_manager import KeyManager

def submit_task(user, task_data):
    # 1. 申请资源
    allocated_key = KeyManager.allocate_key(task_data['model_platform'])
    
    if not allocated_key:
        raise Exception("算力资源繁忙，请稍后重试")

    try:
        # 2. 构造 Payload (携带 Key 信息)
        payload = {
            "key_id": allocated_key.id,
            "key_secret": allocated_key.key_secret,
            "params": task_data['params']
            # ...
        }
        # 3. 入队 Redis ...
    except Exception as e:
        # 4. 如果入队失败，必须释放 Key!
        KeyManager.release_key(allocated_key.id)
        raise e

```

### 步骤 B: 任务执行阶段 (Async Worker)

Worker 负责实际调用，并根据结果反馈 Key 的健康状态。

```python
# worker.py
from app.services.key_manager import KeyManager

def process_task(payload):
    key_id = payload['key_id']
    
    try:
        # 调用上游 API ...
        response = call_sora_api(payload['key_secret'], payload['params'])
        
        if response.status_code == 401:
            KeyManager.mark_as_unhealthy(key_id, "Unauthorized")
            raise Exception("Key Invalid")
        elif response.status_code == 429:
            KeyManager.mark_as_unhealthy(key_id, "Rate Limit")
            raise Exception("Rate Limit")
            
        # 成功逻辑 ...
        
    finally:
        # 【至关重要】无论成功失败，必须释放并发槽位
        KeyManager.release_key(key_id)

```
