### 1. 用户鉴权模块 (Auth Module)
#### 1.1 模块核心职责与设计目标
本模块是系统的安全基石，负责管理用户的生命周期入口与会话安全。鉴于平台涉及付费与积分资产，安全性优于便捷性。

+ **身份验证 (Authentication)**: 确保注册用户的真实性，通过邮箱验证码拦截无效账户，通过密码加盐哈希（Bcrypt/Argon2）防止拖库风险。
+ **会话管理 (Session Management)**: 实现基于 JWT 的无状态认证。
+ **单点登录互斥 (Single Device Enforcement)**: **核心职责**。强制执行“顶号”逻辑（后登录踢掉前登录），防止账号共享与黑产倒卖，确保一个付费账号同时仅在一个设备活跃。
+ **安全风控 (Security)**: 在入口层实施 IP 频次限制（Rate Limiting），防止接口被暴力撞库或短信轰炸。

### 2. 会员与权益模块 (Membership Module)
#### 2.1 模块核心职责与设计目标
本模块负责定义和分发平台的“阶级权益”，是商业化变现的直接支撑逻辑。设计原则是“配置与代码分离”。

+ **权益抽象 (Rights Abstraction)**: 将会员权益参数化（如并发数 `concurrency_limit`、队列权重 `queue_priority`），而非硬编码在业务代码中。
+ **等级配置化 (Configuration)**: 支持 T1-T5 等级在数据库中动态调整。例如，运营决定 T3 的并发数从 2 改为 3，只需修改数据库配置，无需发布新版本代码。
+ **权益查询服务**: 为其他模块（特别是任务调度模块）提供快速、准确的用户权益快照，支撑流控决策。

### 3. 积分与资产模块 (Wallet Module)
#### 3.1 模块核心职责与设计目标
本模块充当平台的“中央银行”，负责一切与积分资产相关的原子性操作。核心目标是账务准确，零误差。

+ **资产一致性 (Asset Consistency)**: 使用数据库事务（Transaction）和悲观锁（Pessimistic Locking）处理 CDK 兑换，杜绝高并发下“一码多兑”或“积分丢失”的问题。
+ **流水审计 (Audit Trail)**: 强制记录每一笔资产变动（充值、消费、退款、赠送）。任何余额的变化都必须能在流水表中找到对应的记录，实现可追溯。
+ **充值核销**: 管理 CDK 的生命周期，支持一次性码和活动通用码的区分处理。
+ **交易闭环**: 配合任务模块，实现“预扣费 -> 失败退款”的闭环逻辑，保障用户权益。

#### 3.2 API 接口定义 (Controller: `app/api/wallet.py`)

def redeem_cdk(user_id, code):
    """
    1. 开启 DB 事务。
    2. SELECT * FROM cdk WHERE code=code FOR UPDATE (悲观锁防止并发)。
    3. 校验状态 (未使用、未过期)。
    4. UPDATE cdk SET status=1, used_by=user_id。
    5. UPDATE users SET balance = balance + value。
    6. INSERT INTO transactions (类型=充值)。
    7. 提交事务。
    """

def check_and_deduct_balance(user_id, amount, task_id):
    """
    (任务提交时调用)
    1. 查余额，如果 balance < amount 抛出 '余额不足'。
    2. UPDATE users SET balance = balance - amount。
    3. INSERT INTO transactions (类型=消费, related_id=task_id)。
    """

### 4. 任务调度与模型网关 (Tasks Module)
#### 4.1 模块核心职责与设计目标
本模块是系统的“中枢神经”和“执行手”，负责统筹任务的生命周期、流量控制及上游交互。

+ **流量整形 (Traffic Shaping)**: **核心职责**。在任务进入队列前，依据用户的会员等级（T1-T5）实施并发限制。若超过配额，直接在 API 层拦截并报错，保护后端算力资源不被单一用户耗尽。
+ **任务编排 (Orchestration)**: 管理任务从“提交 -> 预扣费 -> 入队 -> 调度 -> 执行 -> 结果回传”的全流程状态流转。
+ **优先级调度**: 利用 Redis 多队列机制，确保高等级会员（T4-T5）的任务优先被 Worker 获取和处理。
+ **模型网关 (Gateway)**: 屏蔽底层模型（Sora, MJ）的差异，向下游提供统一的参数接口，向上游处理鉴权、重试和错误映射。
+ **轻量化交付**: 直接透传上游返回的资源链接（不进行服务器转存），降低系统带宽与存储压力。

    """
    1. 【并发检查】:
       current_running = db.query(Task).filter(status.in_(['pending','processing'])).count()
       limit = get_user_concurrency_limit(user_id)
       if current_running >= limit: 抛错 "任务过多，请等待或升级会员"。

       cost = get_model_price(task_data['model']) * task_data['duration']

       redis.rpush(queue_name, json.dumps(task_info))

### 5. 管理员模块 (Admin Module)
#### 5.1 模块核心职责与设计目标
本模块提供系统的上帝视角与干预能力，服务于运营人员。

+ **资源生产 (Resource Generation)**: 负责批量生成 CDK（充值卡密），支持按批次管理，作为唯一的“印钞机”。
+ **用户风控干预**: 具备强制封禁、解封用户账号的能力，用于处理违规用户。
+ **数据看板**: 提供系统运行的关键指标（流水、消耗、用户量），辅助运营决策。
